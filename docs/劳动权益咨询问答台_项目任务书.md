# 劳动权益咨询问答台

## 一、课程设计目的

劳动者在工资、加班、离职、社保、工伤等方面常有疑问，但劳动法条款多、情形复杂，普通人难以判断自己的权益边界。把公开的劳动法规与政策整理为知识库，用自然语言即可获得带依据的答复，能降低咨询门槛。

本项目将公开的劳动法规与政策资料整理为知识库，使用者用自然语言提问即可获得回答，并同步展示答案所依据的文件名称与原文片段。系统对知识库中未覆盖的问题必须明确说明，不得生成没有依据的内容。

## 二、设计内容与任务要求

### 2.1 项目场景与核心流程

使用者提交劳动权益相关的问题；系统检索法规知识库并组织回答；使用者可就同一事项连续追问。

核心流程：`资料导入 → 提交问题 → 知识库检索 → 生成回答 → 展示来源`

### 2.2 必做功能

1. **资料上传与列表**
   - 支持上传 PDF、Word、TXT 格式的法规与政策资料（须为公开资料），展示文件名与导入状态。
2. **法规知识库构建（RAG 基础）**：将导入的资料切分为知识片段并建立检索索引，片段需保留来源（文件名与片段序号）；语料范围、切块粒度与检索方式由学生自行设计。
   - 导入后自动切分为知识片段，按文件归组展示，可查看单个片段原文。
3. **权益问答与来源展示**
   - 接收自然语言提问，返回分点组织的回答（含适用情形、依据条款、处理建议）。
   - 回答下方展示命中的来源文件名、原文片段与相关度，支持展开查看。
   - 回答通过流式方式逐段呈现。
   - 多轮追问：支持“那试用期被辞退有补偿吗”“仲裁时效是多久”这类依赖前文的追问。
   - 连续对话不少于三轮时，系统仍能正确理解指代对象。
   - 支持新建会话，新建后不继承上一轮历史。
4. **无依据问题处理与合规提示**
   - 检索无结果或相关度过低时，明确输出未找到依据的提示。
   - 不得由模型自行补全听起来合理但无来源的内容。
   - 合规提示：涉及具体维权路径与时效的回答必须附“咨询当地劳动监察或法律援助”提示。
5. **结果记录与测试评测**
   - 设计 15 条测试问题，其中 10 条知识库内有依据、5 条知识库内无依据。
   - 运行评测，统计回答正确率与无依据问题的拒答率。
   - 测试问题清单与评测结果作为交付内容的一部分。

### 2.3 选做功能

以下为进阶能力选做项，不做不影响基本验收：

1. 将测试集从 15 条扩充到 50 条以上，统计准确率、拒答率与引用命中率，形成量化评测表。
2. 设计至少两种应答风格（如“劳动者通俗版”“严谨条款版”），由用户在页面切换。
3. 对高频无依据问题做集中归纳，生成一份“待补充资料”清单并展示来源缺失位置。
4. 检索策略对比实验：对比不同切块粒度、不同 Top-k、是否启用重排（Rerank）对引用命中率的影响，输出对比表与结论。

### 2.4 技术要求

本项目技术要求（开发语言 Python 3.11，后端可选用 FastAPI，AI 编排基于 LangChain）：

1. **业务提示词（Prompt）**：使用 Python 编写本项目专属的业务提示词，明确角色定位（劳动权益咨询辅助）、任务范围、输出格式（分点回答 + 依据 + 合规提示）与边界情形的处理方式，并在设计说明文档中说明设计思路。提示词建议集中管理（如 `prompts.py` 或独立配置文件），便于调参与复用。
2. **知识库与引用追溯（RAG）**：基于 LangChain 构建知识库检索链路。知识库切片需保留来源文件名与片段序号（作为 chunk 元数据），确保回答中引用的原文片段可追溯到原文件；检索命中的来源信息应随回答一同返回并展示。
3. **业务工具（Tool）**：实现一个业务工具（查询仲裁时效、查询社保缴纳规则、生成维权材料清单，三选一）。使用 LangChain 的 Tool 机制（如 `@tool` 装饰器）定义工具，明确工具名称、入参说明与返回值结构；页面需展示工具名称、入参与执行结果。

## 三、进度安排

| 阶段 | 主要工作 | 可运行结果 |
| --- | --- | --- |
| 需求与工程 | 明确使用场景与操作边界，收集公开法规资料，启动工程并跑通参考示例。 | 工程可启动，能用示例资料完成一次问答。 |
| 资料准备与提示词设计 | 整理并导入法规资料，编写业务提示词，调整页面文案。 | 用自己的资料完成问答，回答符合权益口径。 |
| 引用验证与拒答调优 | 验证来源可追溯，测试多轮追问，调整无依据拒答与合规提示。 | 回答均可追溯到原文，库外问题明确拒答并附合规提示。 |
| 测试集与评测 | 设计 15 条测试问题并运行评测，统计正确率与拒答情况。 | 评测脚本输出准确率与拒答率数据。 |
| 完善与验收 | 处理异常输入，整理资料清单、数据文件、配置样例、README 与演示数据。 | 项目可独立启动并展示完整的问答与回查流程。 |

## 四、交付物要求

1. **项目成果包 ZIP**：包含源码、知识库资料（须为公开资料）、数据持久化说明、配置样例和 README，能够按照说明独立启动。
2. **项目设计说明文档 DOCX**：说明项目背景、业务流程、功能设计、数据结构、提示词设计、检索方案、评测结果与关键页面，内容与最终代码及运行结果一致。
